# Google申込から公式LINEの参加QRを受け取る

既存のGoogle Formへの申込を維持し、受付済みの回答だけをUnity QRへ渡します。Unity計測ID・既存のGrowthConfirmationトリガー・フォームの既存項目は変更しません。

## 初期設定（運営のみ）

1. Unity QR側の更新・バックアップを完了し、専用の`QR_FORM_SECRET`をCloudflare secretとして安全に設定します。LINEのシークレットや既存の計測キーを流用しません。
2. **現在使っているGoogle Form**からApps Scriptを開き、このリポジトリの`integrations/google-form/RegistrationQr.gs`を新しいファイルとして追加します。スプレッドシート側のスクリプトではありません。
3. Apps Scriptの「プロジェクトの設定 → スクリプト プロパティ」に同じ`QR_FORM_SECRET`を保存します。チャットやソースコードへ貼りません。
4. `setupUnityRegistrationQr`を1回実行し、Googleの権限承認を行います。任意の照合項目を追加し、実際のprefill entryを取得し、専用Form onSubmitトリガーを登録してからQR側へ公開設定を登録します。再実行してもトリガー・項目は重複しません。
5. QR管理画面でAnalytics公開イベントIDと既存QRイベントの対応を確認します。名前だけでイベントや参加者を結合しません。
6. 本人のテスト申込で「LINEで参加QRを受け取る」を開き、入力済みの「参加QR …」メッセージを送信します。受け取ったQRの名前・イベントを確認してテスト受付します。

必須の既存項目名は`お名前`、`イベント名`、`日時`、`公開イベントID`です。同名項目が複数ある場合は安全に停止します。新規項目名は`Unity申込照合ID（自動入力）`、必須にはしません。実際のentry値はコードへ推測して記入しません。

## 参加者の操作

公開イベントを選択、またはイベント名・日付を自由入力して申込 → 完了画面の「LINEで参加QRを受け取る」→ LINEで入力済みメッセージを**送信** → 申込にある名前・イベントの専用QRリンクを受け取ります。LINEを開くだけでは送信されません。初回は公式LINEの友だち追加が必要な場合があります。

Googleのno-cors応答では保存成功を確認できません。通信が不明でもリンクを表示し、QR側はGoogle Formの受付トリガーが到着した回答だけを有効にします。まだ受付確認が届いていない場合は、再申込せず、時間を置いて同じDMを送り直してください。

公開設定が未接続・無効・取得失敗、旧フォームの場合は、従来の「参加希望」案内へ戻ります。すべてのGoogle申込が自動で紐付くとは表示しません。

## データと障害対応

- ブラウザがランダム32バイトの申込専用コードを作ります。GoogleにはSHA-256ハッシュのみ保存します。匿名計測IDとは別物です。
- 生コードは画面のメモリと、本人が開くLINE送信リンクだけに保持します。サイトのクエリ・localStorage・sessionStorage・Growthイベントへ入れません。画面離脱で消去します。申込専用リンクは他人へ共有しないでください。
- トリガーは受付済みの名前、イベントID・名称・日付、照合ハッシュ、回答IDのハッシュを認証付きAPIへ渡します。回答本文・秘密鍵をログへ書きません。
- Google側のトリガーエラーはApps Scriptの「実行数」で確認します。接続障害・429・5xxは同一内容で最大3回再試行します。永続的な失敗は自動で無限再送せず、運営が原因を直して対象回答を安全に再処理する必要があります。
- ページを閉じた後の専用コード復元は現在ありません。コード紛失時は手動受付・運営確認で対応します。再申込して重複回答を増やさないでください。
- テストはモックのみ。本番Formへの回答作成、実際の秘密設定、公開有効化はこのリポジトリのテストでは行いません。

無効化はQR側の公開設定`enabled:false`と専用トリガー停止で行います。既存のGrowthトリガーやGoogle回答を削除しません。既存ページへ戻すときはフロントの前コミット`85c4014f6675b8d20177941a01326190d973e7e5`を参照してください。

## 実装確認（2026-10-12）

Nodeの自動テスト19件成功。Chromium・WebKitで既存申込、初参加／再参加、自由入力、旧3項目フォーム、申込送信の重複防止、公開設定なし、通信結果不明、4画面幅、QR受取リンク、ハッシュのみのフォーム送信、計測へのコード非混入、離脱時消去を確認しました。WebKitのクリップボードはテスト用モックで、実機LINEへの切替と実際のGoogle保存は運営本人のテストが必要です。

本番のGoogle FormやApps Scriptへは書き込んでいません。前提となるUnity QR APIの更新、secret設定、実フォームへのスクリプト追加・実行が未完了なら、従来のLINE案内が維持されます。

## 自由入力対応の更新（2026-10-13）

公開イベントIDがない自由入力にも申込専用コードを作ります。元のイベント名・日付・参加者名、Unity計測情報を変更せず、受理済みフォームのトリガーだけが内部イベントキーを発行します。Unity計測IDで本人を識別しません。

本番反映は次の順序です。
1. 既存フォームに紐づくApps Scriptの `RegistrationQr.gs` をこのブランチの内容へ置き換える。既存GrowthスクリプトとScript PropertiesのQR_FORM_SECRETを維持する。
2. `setupUnityRegistrationQr` を一度実行する。既存の公開イベントID項目を任意入力にし、既存の照合項目・トリガーを再利用する。実entryを推測・変更しない。
3. Unity QRの更新をMacで `npm run cloud:update` により行う（実DBバックアップの取得・復元確認付き）。
4. Analyticsの類似イベント対応、最後にこの申込サイトを公開する。スクリプト未更新のまま先にサイトを公開しない。

同日で「リピーター会／リピーター交流会」など類似名の申込はAnalytics側で一つの受付にまとめます。個人のQRはそれぞれ別です。曖昧な候補や過去の名前表記が確認できない追加は保留します。照合ハッシュが参加予定者タブへ届かない場合、名前で推測して統合せず運営確認を求めます。

確認: Nodeテスト20件、Chromium・WebKitの申込フローが成功。実Google保存・LINE送信・秘密設定の変更は行っていません。
